## 遇到的问题与决策

- **中文文件编码（重要）**：编辑工具新建文件时按系统 ANSI（代码页 936 / GBK）落盘，覆盖已有文件时沿用原文件编码，两者不一致容易被误判。
  - 处理方式：`.md` 统一 UTF-8 **无 BOM**；`.ps1` 统一 UTF-8 **带 BOM**（PowerShell 5.1 需要 BOM 才能正确解析中文）。
  - 教训：转码前必须先检测真实编码（看字节），不能凭猜测直接用 GBK 读取，否则会造成 UTF-8 → GBK → UTF-8 的二次破坏。
  - 实测：`create_file` 新建 `.cs` 文件写入的是 UTF-8，与 `.md` 表现不同，仍以「先检测再决定」为准。
- **日记生成脚本不用 `Set-Content`/`Get-Content`**：改用 `[System.IO.File]` + 显式 `UTF8Encoding`，规避 PowerShell 5.1 默认编码不确定问题。
- **数据库位置**：放系统本地应用数据目录，不放 exe 同目录——避免 Clean/Rebuild 丢数据与安装目录无写权限。
- **连接策略**：短连接 + `Cache=Shared`，每次操作新建并 `using` 释放，避免跨线程共享连接与长期文件锁。
- **`Query<T>` 映射容错**：列名忽略大小写；实体没有的列跳过；`DBNull` 跳过保留默认值；`INTEGER` 读出为 `long`、`REAL` 为 `double`，须经 `Convert.ChangeType` 显式转换否则 `SetValue` 抛异常。
- **参数 `null` 必须转 `DBNull.Value`**：`SqliteParameter` 传 `null` 会抛异常。
- **数量与金额类型**：统一 `double`（SQLite `REAL`），工程量场景精度足够，映射最直接。
- **`PartyAMaterial` 单表贯穿全流程**：申请/入库/出库/退库数量放在同一行不同字段，库存量可推导（入库 - 出库 + 退库），对账更简单。
- **导航形态**：`NavigationViewItem` 内嵌 `MenuItems`，不用 `MenuFlyoutSubItem`（后者会变成点击弹出浮层，选中高亮与展开语义不符）。
- **分组项 `SelectsOnInvoked="False"` 且 Tag 留空**：点击一级分组只展开/收起，不触发导航；`OnNavSelectionChanged` 中 Tag 为空直接 return 做二次保险。
- **占位页导航不能按「页面类型相同」跳过**：`PlaceholderPage` 靠导航参数区分标题，因此 `CurrentSourcePageType == pageType` 的短路判断加了 `pageType != typeof(PlaceholderPage)` 例外，否则从「入库验收」切到「出库领用」标题不会更新。
- **`ListView.SelectedItem` 用事件同步而非 `x:Bind` 双向绑定**：`SelectedItem` 是 `object`，双向绑定到强类型属性需要额外转换器，事件方式更直观且不易出错。
- **`ContentDialog` 必须指定 `XamlRoot`**：WinUI 3 未指定会抛异常，删除确认框已显式赋值。
- **执行顺序**：先建页面类 → 再建 `PageRoutes` → 最后改 `MainWindow`。顺序颠倒会因 `PageRoutes` 引用不存在的页面类型而编译失败。

## 追加：消除 MVVMTK0045 警告（ViewModel 属性写法统一）

### 今日完成

- 6 个 ViewModel（`DashboardViewModel`、`SmallEquipmentViewModel`、`WorkLogViewModel`、`ExcavatorEntryViewModel`、`MaterialLedgerViewModel`、`ImportDocumentViewModel`）共 69 处 `[ObservableProperty]` 字段全部改写为 partial property，`MVVMTK0045` 警告消除。

- 每个 ViewModel 新增构造函数，集中为不可空字符串、日期、初始状态赋值（partial property 不允许字段初始化器）。

### 遇到的问题与决策

- **`MVVMTK0045` 的成因**：`[ObservableProperty] private T _x;` 字段写法在 WinUI 3（WinRT）场景下生成的属性缺少 CsWinRT marshalling 代码，官方建议改用 partial property。项目 Release 启用了 `PublishTrimmed=True`，该警告是真实风险（裁剪后绑定可能失效），因此选择修掉而不是抑制。
- **`LangVersion` 必须设为 `preview`**：先设 `13.0` 会报 `CS9248 分布属性必须具有实现部分` 以及 `The C# language version must be set to 'preview' ...`。MVVM Toolkit 8.4 的生成器对此有硬性检查，只接受 `preview`，改后才正常产出实现部分。这是本轮唯一一次返工。
- **partial property 不允许初始化器**：`public partial string X { get; set; } = string.Empty;` 非法。因此把 `string.Empty`、`DateTimeOffset.Now`、`StatusPending`、`AllMaterialNames` 等默认值移入类构造函数赋值，避免派生一堆 CS8618 警告。
- **属性名必须与原生成名一致**：如 `_earthMaterialCount` → `EarthMaterialCount`，否则 `Pages\*.xaml` 中全部 `x:Bind ViewModel.Xxx` 会编译失败。本轮未改动任何 XAML。
- **`[NotifyPropertyChangedFor(...)]` 在 partial property 上同样有效**，原特性可直接保留；`partial void OnXxxChanged` 钩子签名不变。

### 构建验证结果

- `build_solution` 构建成功（1 个项目通过），`MVVMTK0045` 全部消除，无新增编译错误。
- 除 `MVVMTK0045` 外仍有两处既有提示，与本轮无关：`DEP3321`（部署目标需 Windows Universal Runtime 10.0.28000.0，当前系统 10.0.19045 不满足）、`CommunityToolkit.WinUI.UI.Controls.DataGrid 7.1.2` 在 `wapproj` 下的框架兼容提示。

- **设置用 JSON 而非数据库表**：配置是单例键值对，用表存需额外表结构与反序列化代码，收益为零；JSON 还便于用户手工查看与随数据库一起备份。

- **主题必须设在窗口内容根元素**：WinUI 3 的 `Window` 没有 `RequestedTheme` 属性，只能设在 `NavigationView` 或根 `Grid` 上；`ThemeHelper.Apply` 因此接收 `FrameworkElement`。
- **页脚设置项只能靠 `ItemInvoked` 捕获**：页脚项设了 `SelectsOnInvoked="False"`，点击不改变选中项，`SelectionChanged` 不会触发。而普通菜单两个事件都会触发，所以 `OnNavItemInvoked` 里加了 `route != PageRoutes.Settings` 直接返回，避免同一页面被导航两次。
- **库存流水表而非从现有表推导**：入库/出库/退库/盘点每一笔都需要记录时间与经办人，否则盘点无依据。盘点的 `Quantity` 存差异值（可正可负），汇总时直接相加。
- **`GetStockWarnings` 在内存合并**：甲供与自购分别汇总后按「名称|规格|单位」累加再筛阈值。未用 SQL `UNION` 子查询，因为跨来源聚合可读性差、后续加字段易遗漏。
- **CSV 必须带 UTF-8 BOM**：`FileIO.WriteTextAsync` 写的是无 BOM UTF-8，Excel 会按 ANSI 解析导致中文乱码，因此手动拼 BOM 后用 `WriteBytesAsync` 写入。
- **「打开所在文件夹」用 `Process.Start`**：非打包模式下 `Launcher.LaunchFolderAsync` 常因缺少包身份报「无关联应用」。

- **「表格没显示」是同一根因的连带结果**：`ListView` 原本嵌在 `ScrollViewer > StackPanel` 末尾，表单异常占位后被推出视口。改为根 Grid 四行布局（标题 / 表单滚动区 / 列表标题 / 列表 240px）后，列表始终可见且不随表单滚动。
- **`ExcavatorEntry` 本身不含队伍字段**：18 个属性中无 `Team`/班组，符合「机具进场不记录队伍」的要求，本轮未新增任何相关字段或控件。
- **文件选择器必须绑窗口句柄**：WinUI 3 的 `FileOpenPicker` 是 Win32 对话框，需先 `WindowNative.GetWindowHandle(App.MainWindow)` 与 `InitializeWithWindow.Initialize`，再调用 `PickSingleFileAsync`。

- **公式按指令文档保留而非写死值**：用户指令明确要求「金额与合计必须用公式，不得硬编码」。此前设想的「写计算好的值避免不开 Excel 看到空白」作废——Excel/WPS 打开会自动重算。
- **小型机具模板实际是 25 列（A–Y）三层表头**：指令文档「共26列(A-Y)」与「三队sheet只有25列」自相矛盾，而合并清单只列到 `Y4:Y6`，故按 25 列实现；表头不是计划初判的两层而是三层。
- **`Code` 与 `ImagePath` 无法导出**：模板表头没有这两列，计划的映射表把它们对到 A/B 列是误判（A 实为序号、B 为项目简称）。两者仍完整存库，只是模板无承载位置。

- **导入金额不读模板值**：模板里公式若未重算会读到 0 或旧值，统一按 `数量 × 单价` 重算后写库。

## 追加：发布配置与安装脚本

### 今日完成

- `MaterialManagementApp.csproj`：第一个 `PropertyGroup` 增加 `<SelfContained>true</SelfContained>`（目标机无需预装 .NET 8 Desktop Runtime）与 `<Version>1.0.0</Version>`；`WindowsPackageType=None`、`WindowsAppSDKSelfContained=true` 此前已有，保持不变。
- 非 Debug 配置的 `PublishTrimmed` 由 `True` 改为 `False`。
- 新建解决方案根目录的 `setup.iss`（Inno Setup 6）：`AppId` 固定 GUID、`AppVersion=1.0.0`、`PrivilegesRequired=lowest`、`DisableDirPage=no` 允许自定义安装路径；`[Files]` 只打包 `publish\*`；`[Dirs]` 创建 `{app}\Data` 并设 `users-modify` 权限；`[Code]` 实现升级备份还原。

### 遇到的问题与决策

- **放弃 `PublishSingleFile`**：WinUI 3 依赖 `Microsoft.WindowsAppRuntime.Bootstrap.dll`、`CoreMessagingXP.dll`、`MRM.dll` 等原生 DLL，它们无法打进单文件包且必须位于 exe 同级；强制单文件会导致双击无反应或提示缺少运行时。另外 `Assets\Templates` 下四个模板是 `Content` 文件，单文件发布默认不内嵌，会引发「模板文件缺失」。用户确认改为**自包含多文件**发布。
- **关闭 `PublishTrimmed`**：ClosedXML、DocumentFormat.OpenXml、WinUI 均重度依赖反射，裁剪后运行时找不到类型。此前非 Debug 配置开启裁剪是为了减小体积，引入 Excel/Word 导出后该取舍不再成立。
- **升级数据保护策略**：`ssInstall`（覆盖文件前）把 `Data\MaterialSystem.db` 复制为 `MaterialSystem_backup_yyyyMMddHHmmss.db`，`ssPostInstall`（文件铺完后）再还原。全新安装时因 `FileExists` 为假不产生无意义备份；备份文件还原后**保留不删**，便于用户回滚到升级前状态。还原失败弹 `MsgBox` 给出备份路径，不让用户以为数据丢失。
- **卸载不删 Data**：`CurUninstallStepChanged` 中只提示数据仍保留在 `Data` 目录，不做静默删除，避免误删台账。
- **`PrivilegesRequired=lowest` 的代价**：应用把数据库写在安装目录下，若用户手工改到 `C:\Program Files`，普通用户运行时无法写入 `Data`。已在 `setup.iss` 头部注释中提示建议装到用户目录或非系统盘。
