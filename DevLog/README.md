# 开发日记（DevLog）说明

本目录用于按天记录开发进度，目的是让每次推进都留下可追溯的痕迹，避免「改了哪里、还差什么」靠记忆。

## 文件命名规则

- 每天一个文件，命名格式为 `yyyy-MM-dd.md`，例如 `2024-06-01.md`。
- `_template.md` 为固定模板，**不要修改其小节标题**，脚本依赖它生成当日文件。
- 本 `README.md` 为约定说明，不属于某一天的记录。

## 模板小节含义

| 小节 | 填写内容 |
| --- | --- |
| `## 日期` | 当天日期，与文件名保持一致 |
| `## 今日完成` | 当天已经落地并验证过的成果，按文件/功能列出 |
| `## 进行中` | 已经动工但尚未验证通过的事项，注明卡点 |
| `## 待办事项` | 尚未开始的任务，用 `- [ ]` 复选框，完成后改为 `- [x]` |
| `## 遇到的问题与决策` | 踩过的坑、为什么这样选（技术决策依据），避免以后重复踩坑 |
| `## 构建验证结果` | 构建是否通过、运行时验证了哪些操作步骤 |

## 生成当天文件

在解决方案根目录执行：

```powershell
.\Scripts\New-DevLog.ps1
```

- 当天文件不存在：按 `_template.md` 创建，并把日期占位替换为当天日期。
- 当天文件已存在：**不覆盖**，仅打印已有内容，避免把当天已记录的内容清空。

补建历史某天的文件（例如补昨天的记录）：

```powershell
.\Scripts\New-DevLog.ps1 -Date 2024-06-01
```

## 维护制度

1. **每完成一个开发阶段，必须先写入当日 DevLog 再进入下一步**，不允许「先做完再补记」。
2. 未完成的待办事项，次日新建文件时复制到新文件的 `## 待办事项`，不要留在昨天。
3. `## 遇到的问题与决策` 只写结论与原因，不贴大段代码。
4. 每次记录完执行一次构建验证，并把结果写进 `## 构建验证结果`。
